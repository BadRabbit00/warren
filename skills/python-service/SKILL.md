# Python service

The full Python rule set for coding agents (3.12+). Rule ids `R-PYS-*`; examples live in `references/`. The path rules (`python.md`, `layers.md`, `db.md`, `tests.md`) say the same in short for the main session.

**Priority.** The task and its failing tests > the project's `AGENTS.md`/`CLAUDE.md` > this skill. Follow the neighbouring code's structure and style. Tests are read-only for you; a wrong test means `STATUS: blocked`.

## Layers and naming

Details and examples: `references/layers.md`.

- R-PYS-DIRECTION: dependencies go router → service → repository → model. `core` (config, db, logging) and `domain` (enums, errors, pure rules) are usable everywhere. A lower layer never imports a higher one.
- R-PYS-ROUTER: parse the request, check the role via a dependency, call a service, return the response. No SQL, no `commit`, no business conditions.
- R-PYS-SERVICE: holds the rules and the transaction (one scenario = one commit). Never imports FastAPI, never raises `HTTPException`; raises domain errors.
- R-PYS-REPO: ORM queries only. No `commit`, no HTTP errors, no business decisions.
- R-PYS-ERRORS-MAPPED: domain errors become HTTP responses in one place (`api/errors.py`), one format `{"detail", "code"}`.
- R-PYS-NAMING: entity files are `<entity>_<layer>.py` (`order_service.py`); infrastructure by content (`config.py`, `database.py`). No `utils`, `helpers`, `common`, `misc`. Model `Order`; schemas `OrderCreate/OrderRead/OrderUpdate`; others in full words (`OrderRepository`, `OrderService`). No `OrderSchema`, `OrderModel`, `OrderRepo`.
- R-PYS-NO-FANATISM: a layer exists when it has work. No pass-through classes, no `BaseRepository[T]`, no interface with one implementation unless tests fake that boundary.
- R-PYS-ISOLATED: never import another service's code or connect to its DB; use its API or events. Verify tokens as in `auth-service` (public key, no users table copy).
- R-PYS-FOLLOW: match the existing structure, fixtures and style of the component before adding new ones.

## Data

Details and examples: `references/data.md`.

- R-PYS-ORM-ONLY: SQLAlchemy 2.0 (`select()`, `Mapped[...]`). Raw SQL only for analytics, `COPY`, `LISTEN/NOTIFY`, recursive CTEs or a measured problem; only in a repository, parameterized, with a `# why not ORM:` comment.
- R-PYS-NO-STRING-SQL: never build SQL with f-strings, `%`, `.format()`, `+`. A sort field comes from a whitelist.
- R-PYS-PAGINATE-IN-QUERY: `LIMIT` and keyset/`OFFSET` in the query; `count()` in SQL. Never load rows and slice.
- R-PYS-SELECT-NEEDED: load only the columns and relations you use (`load_only`, `selectinload`).
- R-PYS-NO-N-PLUS-1: no query inside a loop over results; use `selectinload`/`joinedload`/`IN`.
- R-PYS-TX-IN-SERVICE: the service commits; repositories `add`/`flush` only. No HTTP call or email inside an open transaction: after commit or via outbox.
- R-PYS-RACES: read-check-write is a race; use `with_for_update()` or a conditional `update(...).where(...).returning(...)`.
- R-PYS-MIGRATIONS: schema changes only through Alembic. No `create_all()` or DDL at startup. One logical change per migration; read the autogenerated file; expand before contract. A new filter/sort on a big table ships with its index.
- R-PYS-STORES: PostgreSQL by default. Redis holds derived or temporary data only, every key has a TTL, one access module. Files go to S3 (key in the DB), not to the local disk.

## Language, async, I/O

Details and examples: `references/async-and-io.md`.

- R-PYS-TYPES: every function annotated; `mypy --strict` with the pydantic plugin. No `Any` for business data; parse external input into a model at the boundary. Several return values: frozen dataclass, not a tuple.
- R-PYS-ASYNC: nothing blocks inside `async def` (`requests`, `time.sleep`, sync drivers, big file reads). Use `httpx.AsyncClient`, `asyncio.sleep`, `asyncio.to_thread`, `asyncio.TaskGroup`; a created task is awaited or owned.
- R-PYS-EXCEPT: no bare `except:`, no `except Exception: pass`. Catch the narrowest error, re-raise as a domain error with `raise ... from err`. Never return `None` for a failure whose cause the caller needs.
- R-PYS-DEFAULTS: no mutable default arguments; pydantic uses `Field(default_factory=list)`.
- R-PYS-PYDANTIC: v2 API only (`model_validate`, `model_dump`, `ConfigDict(from_attributes=True)`, `field_validator`).
- R-PYS-TIME: aware datetimes (`datetime.now(UTC)`), stored as `timestamptz`. No `utcnow()`.
- R-PYS-IMPORTS: absolute imports from the service root; no imports inside functions to dodge a cycle; no star imports.
- R-PYS-SUBPROCESS: `subprocess.run([...], check=True)` with a list, never `shell=True` with interpolated values; `pathlib.Path` for paths.
- R-PYS-OUTGOING: every outgoing call has a timeout and the retry policy from `docs/POLICY.md`; retry only idempotent calls, with backoff.
- R-PYS-WORKERS: Celery/background tasks are safe to run in parallel and twice: idempotent, a lock or a conditional update, arguments are ids not objects, no state in the process. aiogram handlers are thin and call services.
- R-PYS-STATELESS: no state in the process. Data in the DB, cache/locks/rate limits in Redis, files in S3, schedules in one scheduler.

## Config, logging, runtime

Details and examples: `references/config-and-logging.md`.

- R-PYS-CONFIG: one module reads env (`core/config.py`, pydantic-settings); nothing else calls `os.getenv`. Variables carry a service prefix. A new variable goes into the config module and `.env.example` in the same change. Required values fail at startup.
- R-PYS-LOGGING: `structlog.get_logger(__name__)`, key-value fields, no `print`, no secrets or personal data in logs.
- R-PYS-NIX: no venv, no `pip install`. Run everything as `nix develop -c <cmd>`. A new dependency is reported, not added.

## Tests

Details and examples: `references/testing.md`.

- R-PYS-TEST-FIRST: make the given failing tests pass; confirm they fail for the stated reason first. Code behaviour, never test data.
- R-PYS-TEST-REAL-DB: tests run on the production DBMS with the schema from migrations. No SQLite, no `create_all`.
- R-PYS-TEST-BOUNDARY: fake only what is outside (external APIs, LLM, email, payments, time, randomness); never your own repository in a repository test.
- R-PYS-TEST-OUTCOME: assert results (return, DB state, response, event), not call order. Names state behaviour: `test_paid_order_cannot_be_cancelled`.
- R-PYS-TEST-NO-SKIP: never delete, weaken or skip a red test; no `sleep` for waiting.

## Checks before you hand back

1. `nix develop -c pytest <task tests> -q` - numbers in the report; no skipped.
2. `nix develop -c ruff check <path>` and `nix develop -c ruff format --check <path>`.
3. `nix develop -c mypy --strict <package>` - clean, no new `# type: ignore` without a one-line reason.
4. `git diff`: only files of the write set; no `print`, no `Any`, no `os.getenv` outside config, no `commit` in a repository, no `HTTPException` in a service.
